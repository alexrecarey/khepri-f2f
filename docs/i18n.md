# Translating the app

Everything the app says lives in `src/i18n/<language>.js`; `en.js` is the
source, the others carry the same keys (`src/i18n/locales.test.mjs` fails on a
missing key, a lost `{placeholder}` or a lost `<tag>`).

- A message is a string with `{name}` placeholders. One that depends on a
  number has `_one` / `_other` forms and is asked for as the bare key with
  `{count}` (`t('picker.units', {count: 3})`). `<a>…</a>`, `<b>`, `<kbd>` mark
  what a component draws around the text (`Rich` in `src/ui/i18n.jsx`).
- Components get `t` from `useT()` (`src/ui/i18n.jsx`); App provides it for the
  language `src/state/language.js` resolves. Pure code takes `t` as its last
  parameter and defaults to English (`tEn`), so the tests and the Worker's link
  previews stay English without passing it.
- The rules decide on the army's English tokens (weapon names, properties,
  "+1B", "BS Mode"). Only what they show goes through `t`; a line that the
  code needs to recognise carries a flag (`aro`, `cont`, `plain`), never a
  match on its words.
- Terms Corvus Belli translates itself (extras like "+1B" -> "+1R", weapon
  modes, unit types) come from the army's names file (`names.<lang>.json`) as
  `army.terms`; `t.term('extras', '+1B')` reads them.
- The game terms used in Spanish, with their source, are in
  `src/i18n/glossary.md`. New strings go into `en.js` and every other
  language in the same change.

Why not i18next (as infinitystats does): it would add more to the main
chunk than the whole English copy, and this app needs neither its on-page
copy editor (copy is tested on previews) nor its ICU plural engine (two
languages, `_one` / `_other` cover them).

- Distances: state and URLs hold cm; `t.distance(cm)` gives the number in the
  language's unit (`dist.cmPerUnit`: English inches, Spanish cm) and
  `t.inchText` converts the Army's inch values ('+2"') in text.

Adding a language: its file here, the loader in `src/i18n/index.js`, and the
lists named in `src/state/language.js`.
